Phase 6.8 behavior notes
------------------------
- Public widgets may declare up to 32 network inputs; button inputs count toward the same limit.
- One network action still carries at most two declared inputs.
- A paired session may now have up to five unacknowledged input actions in flight.
  This is a bounded in-flight window, not an atomic five-event packet. Each action retains
  its own canonical event hash and exact acknowledgement.
- Slot reservation uses an AtomicInteger so rapid taps cannot race past the five-action cap.
- Every activated profile widget has a host-owned X overlay. Pressing X calls
  WidgetNetworkHost.close(), clears pending local invite/action/pairing state, removes the
  runtime from Compose, and returns to the inert click-to-load placeholder.
- Closing a runtime does not erase already-published DHT history.
- The bundled Chess example can send FROM and TO square actions back-to-back without waiting
  for acknowledgement of the first action.
